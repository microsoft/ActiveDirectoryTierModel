## Work Summary

Fixed interactive-console hang in test suite caused by anti-pattern: invoking cmdlets with missing mandatory parameters to test `Should -Throw`.

## Technical Details

**Problem File:** tests/Unit.WinLapsAclOperations.Tests.ps1, lines 309–315  
**Issue:** Two tests invoked Get-TierModelWinLapsAcl with missing -Config and -DomainController parameters  
**Root Cause:** Interactive PowerShell prompts for missing mandatory params; CI hosts throw. Test hangs waiting for input in interactive mode.

**Pattern Fixed:**  
```powershell
# BEFORE (anti-pattern)
It "Mandatory parameters enforced: missing -Config throws" {
    { Get-TierModelWinLapsAcl -DomainController $script:TestDC } | Should -Throw
}

# AFTER (metadata-driven)
It "Config parameter is mandatory" {
    $attr = (Get-Command Get-TierModelWinLapsAcl).Parameters['Config'].Attributes |
            Where-Object { $_ -is [System.Management.Automation.ParameterAttribute] }
    ($attr.Mandatory -contains $true) | Should -BeTrue
}
```

## Reusable Lesson

**Skill Capture:** Test mandatory parameters via `Get-Command ...Parameters['X'].Attributes | Where-Object { $_ -is [System.Management.Automation.ParameterAttribute] }.Mandatory`, NOT by invoking with missing args. The latter is ambiguous across host contexts (interactive prompts, non-interactive throws) and breaks test automation.
